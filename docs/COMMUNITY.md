# Find a small way to help

You can contribute without running a server, sharing your own archive or writing code. Start with the [README](../README.md) for the current sample-book entry point. The [fictional sample](https://app.cleanbookface.org/book.html) needs no account or server setup. You can export it and reopen the downloaded ZIP to try the local reader. The sample is not a public account service or an encrypted circle.

Choose one of the [five starter tasks](CONTRIBUTOR_TASKS.md), check existing issues, and leave a comment if you want to try it. A report of a confusing step is useful work. You may use a chosen public handle; no legal name, personal contact details or fixed time commitment is required. GitHub activity and profile links are public, so a chosen handle alone does not guarantee anonymity.

## Where to put it

- **[Issues](https://github.com/Dynobit/clean-bookface/issues):** a reproducible bug, a specific improvement with a success check, or progress on a starter task. Include only fictional data and the exact version or commit tested.
- **[Discussions](https://github.com/Dynobit/clean-bookface/discussions):** getting-started questions, an idea that needs shaping, or interest in helping maintain an area. If Discussions is unavailable, use a minimal issue for a non-sensitive question.
- **[Private vulnerability reporting](../SECURITY.md):** a suspected security or privacy boundary failure. Do not post exploit details publicly. Follow the security policy if the private form is unavailable.

Do not attach personal archives, member screenshots, invitation links, credentials, private addresses or production logs. Reproduce archive problems with a tiny fictional structure. Public pull-request diffs, including deleted lines, may be sent to a third-party model provider for advisory review; people still decide what to merge. Read [Contributing](../CONTRIBUTING.md) before sending changes.

## Two proposed maintenance areas

These are invitations to contribute, not appointments or claims that anyone has volunteered:

| Area                        | A useful first contribution                                              | Possible ongoing scope                                             |
| --------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| Documentation and usability | Follow a fictional sample journey and clarify one confusing instruction. | Review guides, accessibility findings and newcomer feedback.       |
| Tests and imports           | Add a tiny synthetic archive fixture and a behavioral regression check.  | Review import reports, browser compatibility and fixture coverage. |

A chosen public handle is welcome in either area. Start with a bounded contribution; discuss scope and consent before any appointment or access grant. There is no promised schedule, review turnaround or obligation to keep volunteering. Release and production access are separate responsibilities. [Governance](../GOVERNANCE.md) describes the current owner-maintained state and how an actual appointment would be recorded.
