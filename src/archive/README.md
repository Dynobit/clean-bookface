# Archive implementation notes

`Archive` accepts private staged input selected by the authenticated HTTP layer. Never let an HTTP caller supply a server filesystem path. `enqueueImport(ownerId, path, { format })` returns an opaque job ID; `startWorker()` consumes it on a separate bounded worker thread. One application process runs one worker. Staged data stays invisible until a transaction commits the complete import. Cancellation and parse/validation failure discard staged records and media. Startup retries interrupted work idempotently, using the retained staged input. Account deletion stops its active worker and resumes other owners' queued jobs.

Supported input is Facebook JSON with local media, an extracted folder tree, one ZIP, or a directory containing split ZIP parts. Upload split parts together so media in one part can resolve references in another. Facebook JSON shapes supported are own posts (including `your_posts__check_ins__photos_and_videos_1.json`), photos/albums, `friends_v2`, profile records and message threads. Other JSON categories appear as unsupported/empty in the owner-only report. Missing media and remote URLs are reported; no URL is fetched. HTML export import and shared video are unsupported. Validated MP4 originals in imported attachments can be retained privately. Still photos accept JPEG, PNG, WebP, GIF, AVIF and HEIF when supported by the installed Sharp build; animated images are reported as unsupported.

Strings preserve JSON-decoded Unicode exactly. No blanket mojibake conversion is performed. Explicit message millisecond dates stay milliseconds; other numeric timestamps accept seconds or contemporary millisecond values. Missing dates remain null. Provider IDs are scoped to owner, category and conversation/album identity. Fallback identities use the source file and position (messages additionally include their thread, sender, date and split index). These fallbacks cannot prove that a reshuffled export is the same event, so the import report explains possible duplicates instead of merging equal text. Content changes under a stable identity create a version; previous versions remain private and are included in export until the memory is deleted.

Default budgets live in `types.ts`: 20,000 entries per input, nesting 24, 256 MiB per file, 32 MiB per JSON file, 2 GiB expanded input, 1 GiB compressed ZIP, a compression ratio ceiling of 200 above 1 MiB, 100,000 private records per account, 40 million pixels per image, 5 GiB per account for media/text/revisions, and 30 minutes per import. The worker has a 256 MiB V8 heap limit; Sharp has one processing thread and a 16 MiB cache. These are resource bounds, not hosting benchmarks. ZIPs reject traversal, links, special files, duplicate paths and encryption. Generated image output is bounded to 2,048 pixels in either dimension. Shared WebP copies apply orientation, then strip metadata. Original bytes never stand in for a shared derivative.

All read/list/search/job/export/delete methods scope queries to the supplied authenticated owner. Internal `ArchiveMedia` objects include a filesystem path and original linkage for server use; serialize only the intended public representation. Social media delivery still needs the publication audience check. `isShareableMedia` rejects originals and another owner's IDs. `shareCopy` admits only own-post/photo archive categories and copies only body plus chosen image derivatives. Original conversations, tags, comments, friend records and source metadata are not copied.

`exportZip` streams owner records, prior revisions, a media manifest, private originals and shared derivatives. Combine it with the core account export for a complete member download. No credentials are included. `deleteItem` removes the selected private record and unreferenced originals; separately published copies remain under the social deletion controls. When a publication is deleted, the caller should remove a derivative with `deleteSharedMedia` only after proving no other publication references it. `deleteOwner` cancels import work and purges all owner archive records, revisions, jobs, originals and derivatives.

No automatic import ever calls the social or federation subsystem. This module uses no network client.

Completed or failed HTTP imports remove their whole private `incoming/upload-*` stage. Host maintenance removes abandoned upload/extraction directories older than 24 hours, while preserving queued/running jobs. It also removes metadata-stripped preview derivatives older than 24 hours that no active publication references. Private originals are never age-expired; native uploads create visible private photo records so owners can inspect and delete them. Each maintenance pass has bounded directory scanning and deletion counts. A long-open composer may need its photo prepared again after an unused preview expires.
